============================================================
【如何使用】
============================================================

复制以下命令，按需修改括号中的值，粘贴到终端执行:

  ./compress_videos.sh \
    -i "(填入 源视频文件夹路径)" \
    -o "(填入 输出文件夹路径)" \
    -c (填入 CRF质量值) \
    -p (填入 编码预设) \
    --profile (填入 一键配置，可选) \
    -n (填入 nice优先级) \
    -f "(填入 文件匹配模式)" \
    -b (填入 8/10/12/auto) \
    --subdirs

  有引号的参数保留引号。

  ⚠ 如果使用了 --profile，则 -c 和 -p 无需填写（填了也会被覆盖）。

============================================================
【参数说明 - 概要】
============================================================

  参数            默认值            说明
  ───────────────────────────────────────────────────────────
  -i, --input     (必填)            视频输入目录，
                                     如："./video"
  -o, --output    自动，见说明        压缩成品输出目录。
                                     不设置时自动生成: 源目录_compressed
  --profile       (无)              一键配置，覆盖 CRF 和 preset
                                     (详见下方 Profile 说明)
  -c, --crf       22                质量值 
                                     (详见下方 CRF 说明)
  -p, --preset    slow              编码速度
                                     (详见下方预设说明)
  -n, --nice      10                进程优先级，数字越大越不影响前台
                                     (详见下方 nice 说明)
  -f, --filter    *.mp4             要压缩哪种文件，
                                     如: *.mp4 或 *.mov
  -b, --bit       auto              编码色深: 8/10/12/auto (默认 auto)
                                     8   = 8-bit (yuv420p，最兼容)
                                     10  = 10-bit (yuv420p10le，减少色带)
                                     12  = 12-bit (yuv420p12le)
                                     auto = 跟随源文件色深
  --subdirs     —                 添加此参数时，递归处理子目录中的文件
  --no-notify   —                 添加此参数时，禁用完成通知

============================================================
【参数说明 - CRF 值是什么？】
============================================================

  CRF (Constant Rate Factor) 控制输出视频的质量。
  数字越小 = 质量越高 = 文件越大
  数字越大 = 质量越低 = 文件越小

  x265 的 CRF 范围 0-51，默认 28（约等于 x264 的 CRF 23）。

  CRF 值速查 (基于 ~16Mbps 手机视频实测):
  ─────────────────────────────────────────────────────────
  14-16   视觉无损 — 肉眼难以区分差异，适合收藏归档
  18-20   极高画质 — 微小差异，适合日常高质量使用
  22      高画质   — 默认值，画质与体积的平衡点
  24      中等画质 — 细节略有损失
  26-28   较低画质 — 明显压缩痕迹，适合预览/草稿

  注意: CRF 与码率的关系是内容相关的，无法用公式准确预估。
        不同视频在相同 CRF 下输出码率可能相差 2 倍以上。
        建议先用一小段视频测试，确认效果后再批量处理。

============================================================
【参数说明 - 编码预设是什么？（重要：x265 与 x264 相反）】
============================================================

  ⚠ 重要: x265 的 preset 行为与 x264 相反！

  在 x264 中: 越慢的 preset → 文件越小 (压缩更高效)
  在 x265 中: 越慢的 preset → 文件越大 (保留更多细节，质量略好)

  这意味着在相同 CRF 下:
    slow     → 文件最大，质量略好 (SSIM +0.004~0.007)
    ultrafast → 文件最小，质量略差

  实测数据 (源 16.27Mbps, CRF 18):
  ─────────────────────────────────────────────────────────
  预设          输出码率    占源比例    SSIM      相对耗时
  ─────────────────────────────────────────────────────────
  ultrafast     7.5 Mbps    46%        0.9828    1× (最快)
  fast          6.4 Mbps    39%        0.9850    1.5×
  slow          12.1 Mbps   74%        0.9895    3× (最慢)

  推荐:
    - 收藏/归档: slow (质量最优，但慢 3 倍)
    - 日常使用: fast 或 medium (速度与质量平衡)
    - 快速处理: ultrafast (最快，配合低 CRF 14-16 可接近 slow 的效果)
    - 夜景/复杂内容: ultrafast (slow 在复杂内容上优势消失，不值得 3× 时间)

  更多技术细节请参阅: x265_encoding_guide.md

============================================================
【参数说明 - Profile 一键配置是什么？】
============================================================

  --profile 参数提供预设的 CRF + preset 组合，免去手动调参。
  使用 --profile 会覆盖 -c 和 -p 的值。

  可选 Profile:
  ─────────────────────────────────────────────────────────
  Profile       Preset      CRF    场景说明
  ─────────────────────────────────────────────────────────
  archive       slow        18     收藏归档: 质量优先，速度最慢
  balanced      fast        20     日常使用: 速度质量平衡 (推荐)
  fast          ultrafast   14     快速处理: 最快，文件较大
  max-compress  slow        24     极限压缩: 最小体积，可见画质损失
  ─────────────────────────────────────────────────────────

  预期输出 (基于 ~16Mbps 手机视频实测):
    archive      → 约 60-80% 源体积, SSIM ~0.990, 耗时 3×
    balanced     → 约 40-50% 源体积, SSIM ~0.985, 耗时 1.5×
    fast         → 约 60-95% 源体积, SSIM ~0.988, 耗时 1×
    max-compress → 约 20-35% 源体积, SSIM ~0.982, 耗时 3×

  示例:
    ./compress_videos.sh -i ./Video --profile archive --subdirs
    ./compress_videos.sh -i ./Video --profile balanced -b auto

  注意: 也可不用 profile，直接用 -c 和 -p 自由组合。
        详见 x265_encoding_guide.md 了解如何自行选择参数。

============================================================
【参数说明 - nice 优先级是什么？】
============================================================

  nice 控制进程的 CPU 优先级，取值范围为[0,19]的整数。
  数字越大，优先级越低，越不抢占其他程序。


  0    正常优先级 — 和其他程序平等竞争 CPU，适合过夜或无人值守时使用
  10   低优先级  — 有其他程序运行时主动让出 CPU
  19   最低优先级 — 几乎不抢占 CPU，适合边用电脑边压缩

【一键启动】
============================================================

如果懒得读上方指南，可直接使用 profile 一键启动：

  # 日常使用 (推荐) — 速度与质量平衡
  ./compress_videos.sh -i "./Video" --profile balanced --subdirs

  # 收藏归档 — 质量优先，速度较慢
  ./compress_videos.sh -i "./Video" --profile archive --subdirs

  # 快速处理 — 最快速度
  ./compress_videos.sh -i "./Video" --profile fast --subdirs

  # 极限压缩 — 最小体积
  ./compress_videos.sh -i "./Video" --profile max-compress --subdirs

  # 完全自定义
  ./compress_videos.sh \
    -i "./Video" \
    -o "./Video_compressed" \
    -c 20 \
    -p slow \
    -n 10 \
    -f "*.mp4" \
    -b auto \
    --subdirs

将待压缩文件放入该目录下的 /Video 文件夹中，
压缩结果将被存放至该目录下的文件夹 /Video_compressed .
